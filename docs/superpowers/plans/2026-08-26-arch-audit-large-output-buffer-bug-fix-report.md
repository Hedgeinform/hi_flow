# Implementation Report: ArchAudit Large Dependency Graph Output

**Spec:** `docs/superpowers/plans/2026-08-26-arch-audit-large-output-buffer-bug-fix.md`
**Date:** 2026-08-26
**Status:** completed

## Accepted contract

The installed hi_flow ArchAudit runtime must pass complete dependency-cruiser JSON to the parser, including reports larger than Node's default synchronous child-process buffer. It may recover complete JSON from a legitimate non-zero dependency-cruiser exit, but it must never treat `ENOBUFS` partial stdout as a complete report.

## Reproduction proof

- RED used a real temporary bundled CLI that emitted valid JSON larger than 2 MiB. The previous implementation returned a string truncated at position `1,114,112`, and `JSON.parse` failed with `Unterminated string`.
- A separate injected `ENOBUFS` failure with partial stdout proved that the previous catch branch returned the partial string instead of throwing.

## What was done

- Added a bounded 64 MiB `maxBuffer` only to the full dependency-cruiser audit invocation.
- Made `ENOBUFS` fail closed before the existing non-zero-exit stdout recovery, with a contextual error stating that partial JSON was discarded.
- Preserved complete dependency-cruiser JSON emitted on legitimate non-zero exits.
- Added a real combined regression for a 2 MiB JSON report with `exitCode = 1`, plus explicit partial-stdout rejection coverage.
- Regenerated the shipped runtime and synchronized hi_flow manifests at `0.15.3` and the internal ArchAudit package/lock at `0.3.3`.

## Deviations from spec

- The large-output fixture was strengthened after independent review to combine output above 1 MiB with a real non-zero child-process exit. No production scope changed.
- Architecture audit was explicitly skipped because the fix changes only the limit and failure classification of an existing child-process adapter; no architecture boundary or target contract changed.
- Behavior Registry and Active Issues were left unchanged because this is a fully verified implementation deviation with focused executable coverage and no remaining defect.

## Issues discovered

- The temporary worktree initially contained stale ignored dependencies that did not match the lock-file versions and produced different generated bytes. Final build and verification used the already installed lock-matching dependency set; no dependency installation or lock change was required beyond the package version bump.
